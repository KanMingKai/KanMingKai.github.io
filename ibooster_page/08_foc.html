兩圈套在一起:外圈說「要多少電流」,內圈負責「真的把電流打出來」
這張圖在講一件事:串級。 整個系統只有一個目的 —— 讓踏板實際行程 X_padel 跟上駕駛者要的行程 x_padel_ref。 但控制器沒辦法直接命令「行程」,它能命令的只有馬達電流。所以中間拆成兩圈: 外圈把行程誤差換算成一個 q 軸電流命令 i_q_ref; 內圈只管把 i_q 追到 i_q_ref。 外圈慢(受機構慣量與油壓響應限制)、內圈快(只受電氣時間常數限制),兩者頻寬差一個數量級以上, 外圈才能把內圈當成「命令即到位」來設計 —— 這是串級能成立的唯一前提。
四條路徑分別是。 外迴路 x_padel_ref → 誤差 → 踏板行程控制器,再與前饋項相加得 i_q_ref; 內迴路 i_d_ref/i_q_ref → 兩個電流控制器 → 加解耦項得 u_d/u_q → 反 Park → SVPWM; 功率級與馬達 六路閘極訊號 → 三相逆變器 → U/V/W → PMSM → F_Motor 推螺桿載具; 回授與座標轉換 兩相相電流 i_a/i_b → Clarke → Park → i_d/i_q,轉子角 θ 同時餵給 Park 與反 Park。 虛線框代表感測器,虛線代表非接觸量測(磁鐵 → 行程感知器)。
為什麼 i_d_ref 固定為 0。 d 軸電流只產生磁通、不產生扭矩;把它壓到 0,同樣的電流幅值全部拿去出力,銅損最小、扭矩常數最線性。 這是表面式永磁馬達在基速以下的標準做法(不做弱磁時)。
解耦項是前饋,不是回授。 馬達的電壓方程本身就含交連項:u_d = R·i_d + L_d·di_d/dt − ω·L_q·i_q、 u_q = R·i_q + L_q·di_q/dt + ω·L_d·i_d + ω·ψ_f。 圖上那兩支從上方進來的箭頭,就是把已知的 −ω·L_q·i_q 與 +ω·ψ_f 直接補進去, 讓 PI 只需要處理剩下的一階項。少了它,轉速一高,兩軸互相拉扯,PI 得靠積分去追,響應會明顯變鈍。
前饋那條斜線是助力曲線。 x_padel → i_q 的靜態對應直接從命令算出「大致該出多少力」,PI 只負責補殘差。 這是助力系統的重點:駕駛者要的是「踩多深給多少助力」的一致手感,靠 PI 追誤差追出來的手感會滯後。
與原圖的差異。 方塊的相對位置與訊號的來源、去向皆與原圖一致,走線經過重排以減少交叉。 仍有三處交叉(θ 與 i_d 回授各跨過 i_q_ref 一次、i_b 量測線跨過 U 相一次),已用跳線弧標示為「交叉不相接」; 凡是相接的地方都畫實心接點。 原圖以 θ̇ 標記轉子電氣角速度,此處寫成 ω,是同一個量。 原圖的逆變器與 i-Booster 方塊內嵌實物照片,此處改為線稿 —— 頁面規則不引用外部圖片,且線稿在深淺兩種主題下都不會糊掉。 θ 在原圖中由 i-Booster 方塊引出,此處沿用(實體上是馬達端的轉子位置感測,經滾珠螺桿與載具位置一一對應)。
此處未涵蓋。 原圖的 u_q 解耦僅補 ω·ψ_f,未含 ω·L_d·i_d 項 —— 在 i_d≈0 的操作點下這一項本來就近似為零,故沿用原圖不補。 另外,電流控制器與行程控制器的增益、取樣率與時序(內外圈的分頻)、SVPWM 的扇區判斷與作用時間計算(見SPWM vs SVPWM)、 死區補償、以及 i-Booster 內部的兩級齒輪與滾珠螺桿機構(見作動原理動畫),均不在本圖範圍。 本圖是控制結構圖,不是電路圖也不是機構圖。
